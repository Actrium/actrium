## 1. 目标

按照 RFC 分 7 个阶段，将 Actr 的 WebRTC 子系统从 webrtc-rs 0.14 升级到 v0.20.0，并重构为
`RtcConnectionManager` + 多 `RtcPeerController` + `PeerConnectionSession` 的目标架构。每个功能单独
提交 commit；技术经理按 RFC 验收标准逐阶段验收；高级测试保证全量测试通过。

## 2. 三 Agent 协作模型

| 角色 | 模型 | 职责 | 产物 |
|------|------|------|------|
| **senior-dev**（高级开发） | opus | 按 RFC 实现 7 个阶段，每个功能单独 commit；不改旧 0.14 生产路径（Stage 1 纯增量） | 可编译、可测的代码 + commit 序列 |
| **tech-manager**（技术经理） | opus | 严格按 RFC 每阶段退出标准逐条验收实现是否完整；不放过缺失项 | 验收报告（通过/不通过 + 证据） |
| **senior-tester**（高级测试） | sonnet | 跑 `cargo fmt` / `cargo clippy --fix` / `cargo test --workspace`；非逻辑问题不改测试用例；保证改造后测试全绿 | 测试结果 + 最小测试修复 |

执行管线（每阶段）：

```
senior-dev 实现 → tech-manager 验收 → (若不通过) senior-dev 修补 → senior-tester 测试 → 进入下一阶段
```

## 5. 关键发现与偏差

### 5.1 webrtc 0.20.0 真实 API vs RFC 假设（Stage 1 验证）
RFC 执行模型假设**准确**（Sans-I/O rtc core + 高层 async driver、`PeerConnectionBuilder` + 统一 `PeerConnectionEventHandler` 9 回调、对象安全 PC/DataChannel、`poll()`/`try_send()`/`writable()`/`outstanding_bytes()`、Runtime 抽象、restart_ice、NAT 1:1、IPv4/IPv6、TURN/UDP）。与 RFC 的**差异**（以真实 crate 为准，已录 capability matrix）：
- `DriverExited` 无回调源（handler 无 driver-exit 回调）。
- host candidate 仅来自显式 bind socket——v0.20 无接口枚举、`0.0.0.0` 不展开 → `LocalAddressProvider` 是关键承载（与 0.14 根本不同）。
- `close()` 直接 abort driver，无 per-channel 优雅 OnClose（poll 路径）；确定性关闭后信号 = send/writable→`ErrDataChannelClosed`。
- send-buffer limit 默认不启（opt-in），Actr 必须显式设置。
