# 保障、证明与成熟度

规范写明不等于系统已经安全。本章固定三件事：模型在什么前提下成立、实现必须另外证明什么，以及对外可以声称到哪一步。

完整推导见 [形式模型](formal/model.zh.md)。配套有限模型回归见 [check_formal_model.py](formal/check_formal_model.py)。

## 1. 形式分析已经给出的结论

在模型写明的假设下：

1. **逻辑自洽。** 可以构造满足全部核心公理的绿、黄、红实例。
2. **相对可靠。** 若 A1–A13 成立，且切面就绪，绿色足以推出当前不存在可执行的模型内隐私泄漏。绿色只保证这次就绪切面，不保证曾经存在一个全图同时世界，也不否定历史上已经发生的泄漏。
3. **弱项不可抵消。** 未受控必红；无红而有未知必黄。增加节点、风险接受、数据输入授权都不能洗绿。同一评定上下文的多份结论取最弱项。
4. **图外出口仍计分。** 跨 Principal 或无效依赖的 Actor `Transfer` 不入图，也不得判受控。
5. **状态、世代与执行隔离。** 状态变化后旧权力失效；挂起期间不得处理应用数据；旧数据不能走新出口；信箱按「当前声明 ∩ 取得世代声明」执行。
6. **发布抗拼接。** 叶子同时绑定 Actor、状态和节点结论；混合快照不能发布。`EncGraph` 对带标签图单射。Merkle 是真树，成员证明为对数路径。
7. **不需要全图分布式提交。** 本地原子废除旧权力即可保证安全。未依赖变化节点的成员可以按 `LocalContinue` 继续自身工作。持续变化只破坏活性，不恢复旧权力。
8. **失联与撤销有上界。** 最高保障必须本地收口；期限相对本地不可回拨时钟。完全离线最迟到凭证到期。
9. **工程前提不会被公式掩盖。** 完整中介、通道、证据覆盖、可信时间和完整发现都不是数学式自动提供的。证明不了，就必须保持黄／红或拒绝建立结论。

因此当前方案是**条件安全系统**：颜色不会比已建模事实更强。它不是「某个 Host 或某次部署已经安全」。

形式文给出了判断关系、迁移系统和发布前置。机器核验分五层：有限载体完全判定、Z3 量词证明（守卫取自与迁移系统共享的单一定义源）、n≤2 迁移系统穷举（含数据世代、对抗性本地时钟、回滚复活专用模型）、联合 transcript 的 Dolev-Yao 握手穷举（双侧独立视图），以及变异回归——把守卫替换成已知坏定义并断言相应检查器必须报警。其中部分 Z3 条目是对共享守卫的定义一致性锁定，不构成独立证明；有界搜索触及状态上限即显式失败。入口是 [proof/check_proofs.py](formal/proof/check_proofs.py)。

加码过程中关闭了若干规范漏洞（Thm 7 缺少当前性、挂起仍可展示绿色、自签、单方 Hello MAC 可重放、旧数据走新出口、编码未定义、验证者可挑选、内容回滚复活旧凭证、目标分类可被声明方改写等），完整清单见 [缺陷表](formal/defects.zh.md)。A2／A4／A5／A6／A8／A9 仍是公理，不是已证现实。

## 2. 证明义务

绿色若要在现实中成立，实现必须逐项交付：

| 义务 | 缺了会怎样 |
| --- | --- |
| Host 对声明外效果的完整中介 | 有效声明不是闭合上限 |
| Native / VM / TEE 实际能力被约束或保守补全 | 只能保持黄或红 |
| 状态权威原子切换并废除旧密钥 / 效果 | 状态变化定理不成立 |
| 握手真实绑定双方 `ActorId + ActorStateId` | 通道不能视为有效 |
| 无根图能发现完整入边和出边 | 可能漏评 Actor |
| Evidence Profile 覆盖日志、调试、管理员和 GPU 路径 | 相应事实保持未知 |
| 非 Actor 目标可判定、可强制且策略可识别 | Transfer 不能判受控 |
| 可信时间不可回拨，期限不可延长 | 失联安全不成立 |
| 密钥和恢复路径能不可恢复失效 | `Retain` 仍存在 |
| 规范编码、哈希、签名和算法迁移无歧义；`EncGraph` 遵守 `actrium/graph/v1` | 抗拼接、抗重放失效 |
| 应用数据打上取得世代，执行点按交集强制 | 旧数据可走新出口，Thm 18 不成立 |
| 同一评定上下文取最弱项，禁止挑选较绿验证者 | 用户可被导向虚假绿色 |
| 状态权威维护单调 `revision` 并进入 `ActorStateId` | 内容回滚复活旧 Capability／旧结论，Thm 10 退化 |
| 目标分类可判定：Actr 端点不得伪装为域名 / API 目标 | 跨 Principal 出口经 TrustedSinks 洗绿 |
| `host_environment_state_fingerprint` 覆盖所有可影响 Transfer／Retain 事实的环境维度 | 同 sid 内环境漂移（管理员权限、调试器、日志配置）不可见，绿色失真 |
| 期限使用执行方本地不可回拨时钟 | 失联上界和对端时钟串用 |
| 评定方核验有效期所用时钟同样不可回拨 | 过期证据与过期结论被本地回拨重新接受 |
| 用户策略求值确定、版本化、原因可追溯 | 同状态可能产生不可解释结果 |
| 并发、分区、重放和降级负向测试通过 | 只能保持 `Specified` |

最难的三处通常是：普通 Native 的旁路闭合、CPU 与加速器的组合证明，以及分布式环境下无根图的完整发现。

## 3. 成熟度

每一项能力、Profile 和对外主张都必须单独标记：

| 状态 | 含义 |
| --- | --- |
| `Specified` | 语义已经写清楚 |
| `Implemented` | 已有实现 |
| `Tested` | 已通过规定的正向与负向测试 |
| `Attested` | 当前运行实例能提供相应证据 |
| `Deployed` | 相关控制已在目标环境启用 |

本目录整体处于 `Specified`。在缺少一致性报告之前，不得把目标架构宣传为当前版本已经满足的事实。

已知、仍会影响对外措辞的实现限制包括：

- Actr 数据路径仍须关闭明文或身份未绑定的回退，并把双方 Actor 身份与会话材料端到端绑定；
- Native / 平台 Host 的能力闭合、状态权威和失联收口尚未作为已测试保证；
- 机密计算与 GPU / NPU 只有语义，没有可引用的厂商 Profile 与现场证据；
- 过渡凭据存储、未闭合的同步加密策略，以及普通 WebView 路径，都不能当成满足本模型的执行边界。

这些限制变化时，改本章和对外说明，不要回头把旧检查表写成现行规范。

## 4. 开发与事故的最低要求

安全相关改动在进入实现前，必须能指出：新增了哪些 Actor、能力或 TCB，失败时由谁阻断，以及对应的负向测试。说不清「谁执行失败关闭」，不得进入实现。

共享安全语义（身份规范化、Capability 验证、通道绑定、`EncGraph`、图聚合、数据世代、Assurance 核验）应集中在可测试的核心实现里，由各平台消费，而不是各端各拼一套结论。

发布材料必须带作用域和成熟度。没有 `Tested` / `Attested` / `Deployed` 证据的能力，对外只能写成目标或实验。紧急撤销针对信任根、发布键、验证者和实例，不靠改文案把红改成绿。

事故处置可以冻结数据面、吊销密钥和撤回信任；不能事后改写当时的技术事实。复盘若发现模型本身有反例，再修订本目录，并同步失效受影响的结论对象。

## 5. 仓库归属

长期看：

- Actr 持有跨实现的 Actor 主体、能力效果、通道、保障图和聚合规范；
- Keel 持有 Guest / Host 能力 Profile 与测试；
- Actrium 持有 Tab 映射、平台 TCB 和用户交互；
- Realm、Workspace 和机密计算服务各自持有部署 Profile 与现场证据。

本目录先作为统一结论入口。拆分时必须保留稳定要求 ID 和交叉链接，避免再出现两套并行语义。
