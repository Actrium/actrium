# 总览与主张边界

一个看似简单的智能应用，往往同时包含本地界面、远端服务、模型、工具、Workspace、日志和第三方 API。品牌、开源、商店审核和传输加密都有价值，但都不能单独回答：

> 这份数据现在可能被谁接触？每个接触点受什么约束？约束凭什么成立？结构一变，数据流会不会真的停下来？

Actrium 把应用看成一张 Actor 图，只评价**当前就绪切面**，不给名字发奖状。新配置只约束新数据；同一评定里不能挑选较绿的验证者。

## 1. 这套模型做什么

它把「应用现在安不安全」拆成可以核对的事实：

1. 谁在跑、跑的是哪份制品、服务于哪个使用主体；
2. 跨越 Actor 边界时，信息可能传到哪里、用完后还能不能恢复；
3. 这些可能效果是否被不可绕过的机制限制住；
4. 证据是否新鲜、是否绑在当前状态上；
5. 结论变弱时，旧密钥、旧通道和旧授权会不会立刻失效；旧数据会不会仍被取得时的声明拦住。

它不判断数据「值不值得保密」，不证明软件绝无漏洞，也不把用户点击「同意」当成技术风险消失。

## 2. 原语是积木，不是互相替代的标签

| 原语 | 能支撑的主张 | 不能单独主张 |
| --- | --- | --- |
| TLS / WebRTC / QUIC | 指定端点之间的链路机密性、完整性、防重放 | 端点不泄露；信令看不到元数据 |
| 有效 Actr 通道 | 明文只出现在互相认证的 Actor 两端 | Actor 内部处理一定安全 |
| Wasm / Keel | Guest 只能走 Host 显式提供的能力 | Host、OS 没有漏洞 |
| OS 沙箱 / 受限 Native | 给定 Profile 内的系统能力被限制 | Native 标签等于 Wasm；内核不可攻破 |
| 代码签名 / 可复现构建 | 制品来源和内容未被替换 | 发布者善意；逻辑没有缺陷 |
| TEE / 机密计算 | 声明范围内的内存和执行可抵御特定基础设施攻击者 | workload 不写日志、不外发、不返回敏感信息 |
| 远程证明 | 某 Attester 对测量和环境给出可验证材料 | 自动完成信任和授权 |
| 应用图与保障结论 | 被强制枚举的可能出口可以闭包、聚合并执行 | 不存在未知漏洞、侧信道或模型记忆 |

链路加密管途中，能力闭合管端点会不会主动带走数据，证明管「现在跑的是不是声称的那个环境」。缺一环，就不能把整图说成已验证。

## 3. 颜色怎么读

Actrium 顶层只用三档，语义固定：

| 颜色 | 含义 | 不是什么 |
| --- | --- | --- |
| 绿 | 当前就绪切面上：图合法、通道有效，每个 Actor 的全部可能出口都确认受控，并确认不存在 `Retain` | 永久认证；全图曾在同一物理瞬间同时如此；软件无漏洞；元数据不可见 |
| 黄 | 没有已确认的未受控泄漏能力，但至少一项必要事实无法确认 | 「稍微安全」；已经泄漏 |
| 红 | 已确认存在至少一项未受控泄漏能力 | 系统目击了一次实际泄漏事件 |

图无效或通道建不起来时，产品应显示「无法建立安全状态 / 通信已阻断」。这不是第四色，也不能用风险接受绕过。

用户配置的是可识别行为模式的可信规则，不是颜色本身。同一评定上下文若有多份结论，取最弱项，不能挑较绿的验证者。风险接受只决定「是否继续跑」，黄仍是黄，红仍是红。能力变大之后重新变绿，只约束新数据；旧数据仍走取得时与当前声明的交集。

## 4. 可以说什么，不能说什么

推荐表述：

> Actrium 根据 Actor 当前状态、有效能力、证据和用户策略，判断一张应用图在**当前就绪切面**上的可能出口是否受控。绿色表示这次核对里指针一致、图就绪、且该切面已经成立。新配置只约束新数据。不是对应用永久、绝对安全的承诺，也不表示所有 Actor 内部状态曾在同一物理瞬间同时如此。

「全过程加密」的正确说法是：数据在受保护链路和受保护存储上以密文存在；明文只应出现在身份已知、边界满足要求的处理环境中。不能说「任何时刻、任何位置都是密文」——计算通常需要在某个受控边界内出现明文或等价可用形态。机密计算的价值是缩小并证明这个边界，不是取消计算时的明文语义。

TEE / GPU 机密计算可以证明硬件状态、测量值和部分内存路径，通常不能从外部凭空证明「应用没有写业务日志」。要约束日志，必须同时具备能力闭合：没有相应出口，或出口被 Host 不可绕过地限制，并且目标落在用户认可的边界内。

公开安全表述在发出前至少要能回答：主体是谁、作用域是什么、信任根是什么、证据何时到期、谁执行失败关闭、哪些风险明确不在范围内。答不上来，就缩小或删除该主张。

## 5. 当前明确不覆盖的问题

- 数据内容的绝对隐私价值或敏感度评分；
- 细粒度数据分类、用途评分、边级或子图安全等级；
- PrincipalId 的生成与现实身份治理；
- 业务「任务完成」的通用语义；
- 地址、时序、流量大小等通信元数据隐私；
- 具体密码套件、默认信任根名单或某家 TEE 厂商的现成认证；
- 对全部软件漏洞、拒绝服务和物理攻击的完整防护。

这些若以后进入模型，必须先有可证明事实、不可绕过执行点和清晰的失效规则，不能只加描述字段或主观分数。
