SECTION 00 · OVERVIEW

Guest 开发指南ACTRIUM MINI-PROGRAM DEVELOPMENT GUIDE

Guest（小程序）是运行在 Actrium 沙箱中的不受信应用代码：业务 JS 经 Keel Engine 的 loadBundle 加载后形成运行实例，通过声明式 UI 与受控能力调用和 Host 交互。本文面向 Guest 开发者，覆盖工程搭建、UI、Host 能力、固定路由 Service RPC、打包与验证。

文档范围与基线

本文以 Actrium f09a82b4、ACTR Hub 155c60c9 为审核基线，描述 Actrium Product v1、keel.guest/1、actr-package/2 和 capability schemaVersion = 1。通用 Keel SDK 中存在某个导出，不代表它能通过 Product v1 构建；未列出或标为系统、内部、legacy 的 host:* 能力和调用方式，不应作为第三方 Guest 公共 API 使用。

整体分层

先建立全局观：Actr Host 是 Actor 运行时；Front Actor 是逻辑 Actor 实例；Front Host 是 Front Actor 的受信宿主部分；Keel Host 是其中负责创建 Guest 沙箱的组件，由 React Native 承载。

关键认知

不是 Native 把 Service 对象逐层传给 Guest。Guest 通过 host:service/<固定路由> 的 named import 取得 call 或 on；真正传递的是 Base64 业务载荷和返回结果，Service target 由 Front 在 Attach 后固定。guest.js 与 Keel Guest 也不是两个概念——前者是 .actr 包内文件，后者是它经加载后的运行实例。

Contract 校验路径

Guest 与 Host 的能力调用走 Keel Contract 类型化路径：rpc() / subscription() 描述符经 dispatch table 路由到 Host 实现。声明了 BoundarySchema 的边界执行 parseInput / parseOutput / parseEvent；TypeScript 泛型本身不会自动生成运行时校验。

SECTION 01 · QUICKSTART

快速开始YOUR FIRST GUEST APP

一个 Guest 应用的核心是会被打包进 .actr 的 JS bundle。Product v1 使用 react、JSX runtime、keel/guest 和静态声明的 host:* 模块；JSX 由自定义 reconciler 转成 render ops 发给 Host 渲染。

开始前准备

准备 Bun、与本文基线匹配的 Actrium/Keel checkout 及依赖，并使用兼容的 actr CLI。以下命令从 package payload 根目录执行；/path/to/actrium 和签名 key 路径需要替换为实际值。发布到新环境时，应重新确认版本基线。

最小可构建示例

工程使用 ESM，入口组件默认导出，构建器自动追加 render footer。keel/guest 与 host:* 必须使用 named imports；这里只使用 v1 白名单中的 View、Text 和 Button。

guest · src/guest.tsx
import React, { useState } from 'react';
import { Button, Text, View } from 'keel/guest';

export default function App() {
  const [count, setCount] = useState(0);
  return (
    <View style={{ flex: 1, padding: 24 }}>
      <Text style={{ fontSize: 20 }}>你好，Actrium</Text>
      <Text>点击次数：{count}</Text>
      <Button title="点我 +1" onPress={() => setCount(c => c + 1)} />
    </View>
  );
}

这个纯 UI 示例不申请 Host 方法，因此合约只声明空集合。使用 Host 或 Service 能力时，再按后文添加描述符和 BoundarySchema。

  version: '1.0.0',

Product v1 模块规则

构建器 external 化 react、react/jsx-runtime、react/jsx-dev-runtime、keel/guest 和 host:*。keel/guest 与 host:* 的 default、namespace、bare import 不能表达能力边界，v1 会拒绝；动态 import、eval、Function 和未登记的 runtime dependency 也不可用。通用 Keel 的 react-native shim 或 keel/reconciler 白名单不能替代这套更严格的 v1 构建规则。

沙箱不是浏览器

TextEncoder、TextDecoder、performance、btoa、atob、Buffer、crypto 等浏览器或 Node 全局不能作为 Guest 依赖。需要 UTF-8、Base64 或计时时，使用上表中的 keel/guest helper。

样式与限制

SECTION 03 · HOST CAPABILITIES

调用 Host 能力KEEL CONTRACT · RPC & SUBSCRIPTION

Guest 通过 host:* 的 named import 使用 Host 已实现的能力。Keel Contract 声明模块、方法和边界 schema；它不能让一个 Host 尚未实现的能力变得可用。第三方 Guest 不应自行发明 host:analytics 等模块名。

统一示例：剪贴板

下面三个 Tab 使用同一个真实模块。parseInput 是运行时校验；rpc<{ text: string }, void> 的泛型只提供 TypeScript 类型，不能替代它。

typescript · src/keel.contract.ts
import { defineKeelContract, rpc } from 'keel/contract';

export const contract = defineKeelContract({
  version: '1.0.0',
  hostModules: {
    'host:clipboard': {
      writeText: rpc<{ text: string }, void>({
        schema: {
          parseInput: (value) => {
            if (typeof value !== 'object' || value === null) {
              throw new Error('clipboard.writeText input must be an object');
            }
            const text = (value as { text?: unknown }).text;
            if (typeof text !== 'string') {
              throw new Error('clipboard.writeText input.text must be a string');
            }
            return { text };
          },
        },
      }),
    },
  },
  guestExports: {},
});

此页是 Actrium Host 维护者示意，不属于 Guest 应用代码。真实实现由 Actrium 注册，Guest 包不能注入 nativeClipboard。

typescript · Host 内部示意
import { implementHostModules } from 'keel/contract';

export const hostModules = implementHostModules(contract, {
  'host:clipboard': {
    writeText: async ({ text }) => {
      await nativeClipboard.write(text);
    },
  },
});
typescript · guest
import { writeText } from 'host:clipboard';

await writeText({ text: 'hello' });

// front-package.toml 还需要声明：
// required-capabilities = ["host:clipboard.write", "ui.render"]
两层名称都要匹配

CLI 会对照 contract 的 hostModules[moduleId][exportName] 校验 host:* 导入；Host 还会把生成 manifest 与 package 的 required-capabilities、平台策略和会话授权交叉验证。contract 中存在某个名称，不等于 package 已获授权。

当前可用的非 Service Host 模块

模块方法说明
host:clipboardwriteText写剪贴板；用户授权
host:local-storagegetItem / setItem / removeItem本地 KV；调用经 Capability Broker
host:speechrecognize / onInterimResult / stop / onStateChangerecognize 需要用户授权；事件订阅和停止使用各自能力声明

typescript · guest · 各能力调用写法
// 本地 KV
import { getItem, setItem, removeItem } from 'host:local-storage';
await setItem({ key: 'draft', value: '...' });
const value = await getItem({ key: 'draft' });   // string | null
await removeItem({ key: 'draft' });

// 语音识别
import { recognize, stop, onInterimResult, onStateChange } from 'host:speech';
const offInterim = onInterimResult(({ text }) => { /* 中间结果 */ });
const offState = onStateChange(({ state }) => { /* recording | finalizing */ });
const { text } = await recognize({ locale: 'zh-CN', continuous: true });
offInterim();
offState();

// 文件选择与缓存附件
import { pick, openPreview, release } from 'host:file-import';
const { files } = await pick({ source: 'files', accept: ['image/png'], multiple: false });
// files: { name: string, base64: string }[]
// cache: true 时返回 { fileId, name, size, thumbnailBase64?, canPreview? }[]，不含原始字节：
const { files: cached } = await pick({ source: 'photos', cache: true });
if (cached[0]) {
  await openPreview({ fileId: cached[0].fileId });  // 原生预览缓存附件
  await release({ fileId: cached[0].fileId });      // 不再需要时释放
}

// 文本转语音
import { speak, stop as stopSpeaking } from 'host:tts';
const { status } = await speak({ text: '你好，Actrium', locale: 'zh-CN' });  // finished | cancelled
await stopSpeaking();

// 更新标签页标题
import { setTitle } from 'host:tab';
await setTitle({ title: '新标题' });

每个被使用的方法都需要对应的 package capability，例如 host:local-storage.getItem、host:speech.recognize、host:tts.speak、host:tab.setTitle、host:file-import.pick。订阅、停止、读取和预览是独立方法，不能只声明 recognize 或 pick 后假设其他方法也自动获批。

Service → Guest 固定事件推送

Product v1 的业务推送使用固定事件模块，不把通用 Engine.sendEvent 或命名事件 Hook 当作公共 Guest API。事件 handler 收到 { event, payloadBase64 }，并返回退订函数；在 React 中应把退订函数交给 useEffect 清理。

typescript · guest
import { useEffect } from 'react';
import { on as onConversationEvent }
  from 'host:service/lattice.v1.ConversationEvent';

useEffect(() => {
  return onConversationEvent(({ payloadBase64 }) => {
    // 使用业务 proto 对应的 decoder 解码 payloadBase64。
  });
}, []);

此用法还需要 service.on package capability。完整示例见 ACTR Hub lattice。

SECTION 04 · BUSINESS RPC

固定路由 ServiceCALL · EVENT · ATTACHMENT

业务 RPC 使用 host:service/<固定路由> 模块。斜杠只分隔模块前缀和完整业务路由；路由本身使用点分名称，例如 echo.v1.EchoService.Echo。包内 proto 定义业务 route 和消息结构，Keel contract 定义 Guest/Host 边界，两者不能互相替代。

代码生成与手写适配

actr gen 可复用 proto 解析和生成基础，但不能直接生成完整 Keel Guest 链路。当前示例通常还需要提供固定路由的 TypeScript 模块声明，以及业务消息的 Protobuf/Base64 编解码。可参考 ACTR Hub echo/guest/echo-wire.ts 和 echo/guest/host-service.d.ts。

Guest 公共 API

导入形式方法输入 / 输出说明
host:service/<route>call{ payloadBase64, timeoutMs? } → { payloadBase64 }固定 route 由 Host 注入；Guest 不传 route
host:service/<event>onhandler 收 { event, payloadBase64 } → 退订函数只接收匹配的固定事件
host:serviceuploadAttachment{ filename, base64, type?, id? } → { attachmentId }固定上传传输；package 能力名是 service.attachmentUpload
裸 host:service 不提供动态业务调用

Product v1 不允许从裸 host:service 导入 call、tell 或 on；只有 uploadAttachment 使用这种固定传输导入。tell 当前未实现，不在本文可用 API 范围内。

RPC 示例

typescript · guest
import { call as echo } from 'host:service/echo.v1.EchoService.Echo';
import { decodeEchoReply, encodeEchoRequest } from './echo-wire';

const out = await echo({
  payloadBase64: encodeEchoRequest('hello'),
  timeoutMs: 8_000,

const reply = decodeEchoReply(out.payloadBase64);

附件上传示例

typescript · guest
import { uploadAttachment } from 'host:service';

const { attachmentId } = await uploadAttachment({
  filename: 'report.pdf',

超时

timeoutMs 默认 30 秒，全局上限 300 秒；应用 contract 可以进一步收紧。示例中的 8 秒、10 秒或 120 秒是具体应用选择，不是所有 Service 的统一超时。

Package 声明

业务 RPC、事件和附件分别需要 service.call、service.on、service.attachmentUpload。使用 Service 的 Front 还需要 [dependencies.service] 和双方共用的 proto contract 文件；只写生成 manifest 不会自动获得这些授权。

SECTION 05 · CAPABILITY MANIFEST

动态代码 fail-on-violation

route、模块 ID 和事件名必须静态确定。动态 import、eval、Function、非字面量 runtime dependency，以及裸 host:service 的动态 route 调用都会被拒绝：

typescript · 反例
const route = prefix + '.List';
await import('host:service/' + route);  // 动态 import + 非固定模块 ID：拒绝

SDK 封装应保留显式 named import 和固定模块映射，不能让生成器根据函数名或运行时字符串猜 capability。

SECTION 06 · SECURITY MODEL

安全与能力模型TWO-TIER CAPABILITIES · FAIL-CLOSED

Actrium 的能力模型分四层。

四层模型

层回答的问题实现依据
1. Front capability哪些 Host 方法可调用（service.call、host:*）能力定义表 + 有效集计算
2. Component whitelist允许渲染哪些 Keel 组件组件白名单（共 12 个）
3. Platform permissionOS 级授权（camera / microphone / location / notifications）osPermission 字段，调用期核对平台授权
4. Service capabilityWorkspace / network / actor / shell 等按实例授予按实例计算有效集（declared ∩ supported ∩ policy ∩ session）

两层受众（audience）

每个 Front capability 都有 audience 属性。这是「能力面向谁开放」的维度，与上面四层正交：

受众范围门槛
third_party绝大多数 Front capability包内声明 + Host 支持 + 授权与 session 约束
system SYSTEM仅面向第一方系统能力第一方签名验证 + 显式 Host policy
🚫 系统身份不能靠这些认定

systemAppType、包放在系统目录、publisher = "actrium"、开发 key 签名——都不能用来认定系统 Guest。只有第一方签名验证通过 + 显式 Host policy 允许才行。

可以申请 ≠ 免授权。第三方调 service 时，仍由 Service 按角色和业务权限决定能否执行；系统 Guest 也仍受用户、组织、平台和 session 约束。

有效能力 = 六个条件的交集

有效能力的精确计算规则：effective = declared ∩ host-supported ∩ audience ∩ grant ∩ platform ∩ session。session 要求 state === 'active' 且在 allowedCapabilities 内。

交互演示 · 勾掉任意一项，能力立即失效
✓declared 声明manifest / 包内声明要用
✓host-supported Host 支持Host 声明支持该方法
✓audience 受众匹配third_party / system 类别允许
✓grant 已授权requiresGrant ≠ none 时必须已授予
✓platform 平台权限camera / mic / location / notifications
✓session 有效会话state = active 且在 allowedCapabilities 内
✓ 能力生效：Guest 可以调用该能力

能力属性

text · 能力属性
name            // 方法级能力名，如 host:clipboard.write
audience        = 'third_party' | 'system'
requiresGrant   = 'none' | 'user' | 'admin' | 'elevated'
osPermission?   = 'camera' | 'microphone' | 'location' | 'notifications'
requiresBroker  = boolean   // 调用期由 broker 消耗，不进有效集
requiresSandbox = boolean   // 调用期由 sandbox 消耗，不进有效集

能力grant备注

授予与撤销

时机行为
安装时只展示 package 申请的 capability，不授予运行权限
创建实例时授予 Service、Workspace 和长期后台能力，写入持久 grant
首次使用交互能力时剪贴板、文件选择、语音识别等即时请求，可选「仅本次会话」
撤销时Actr Host 必须立即失效相关 capability handle，并结束仍在使用它的调用
管理员策略可预先拒绝或约束 scope，但不能在 UI 中伪装成用户同意
SECTION 07 · PROTOCOL

通用 Keel 通信协议INTERNAL REFERENCE · NOT A V1 API WHITELIST

内部协议不等于 Product v1 公共能力

本章面向 Host/Keel 维护者和调试人员，描述通用 Engine 消息。HOST_EVENT、REF_METHOD_RESULT 等消息存在，不代表对应的通用 Hook 可以通过 Product v1 构建。Guest 业务开发仍使用前述白名单组件、named imports 和固定 Service 事件。

底层通信层 Guest 开发者通常不直接触碰，但理解它有助于排查事件和回调问题。

两条通道

通道方向频率链路
render opsGuest → Host高渲染批次（OperationBatch）→ Bridge 编码 → Host 应用批次增量更新
消息Host → Guest低Engine 发送 → Bridge 编码 → 沙箱内消息分发

编码格式为 KBS1 envelope：支持二进制字段（Uint8Array 原始段随行）与函数回调注册/调用；函数 props 编成 { __type:'function', __fnId }，循环引用编成 { __type:'circular' }，复杂类型（Date/RegExp/Map/Set/Error）序列化为 JSON 安全表示。

Host → Guest 消息类型

消息字段说明
CALL_FUNCTIONfnId, args调用已注册的 guest 回调（onPress 等）
HOST_EVENTeventName, payload通用 Keel 命名事件；不是 Product v1 Service 推送 API
CONFIG_UPDATEconfig更新 guest 配置
DESTROY—通知沙箱拆除
REF_METHOD_RESULTrefId, callId, result?, error?通用 Keel RemoteRef 返回值；不表示 Product v1 开放对应 Hook
PROMISE_RESOLVE / PROMISE_REJECTpromiseId, value / error解决 / 拒绝跨边界 promise

→

Bridge 解码出的闭包
→

→

按 fnId 找到原函数
→
5

生命周期事件速查

事件 / 消息方向Guest 应做什么
CONFIG_UPDATEHost → Guest更新配置，触发依赖配置的组件重渲染
DESTROYHost → Guest清理定时器与订阅（沙箱即将拆除）
常见排查清单
  • UI 没出现：组件是否来自 v1 白名单？入口组件是否默认导出？是否出现 component_not_allowed？
  • onPress 没回调：函数 prop 是否已注册为回调？箭头函数每次渲染重建属正常，diff 会更新 fnId。
  • Service 事件没收到：是否使用固定 host:service/<event> 的 on？package 是否声明 service.on？effect 清理是否提前退订？
  • Service 调用失败：模块路由是否为点分完整名称？是否误传 route？生成 manifest 与 package 的 service.call 是否同时存在？
  • manifest 校验失败：是否误把 --capability-manifest 的通用报告当成 --v1-capability-manifest 的运行时文件？
  • Host 侧想看 Guest 日志：console 输出经 __console_* 全局桥接，查 Host 日志管道。
