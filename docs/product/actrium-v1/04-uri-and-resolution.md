## 2. Basic Syntax:

```text
actr://<publisher>/<program>@<version>[/<guest-route>][?<query>][#<fragment>]
```

Example:

```text
actr://notes.example/team-notes@1.4.2
actr://notes.example/team-notes@1.4.2/today
```

Simplified ABNF:

```abnf
actr-uri       = "actr://" publisher "/" program "@" version
                 [ "/" guest-route ] [ "?" query ] [ "#" fragment ]
publisher      = reg-name
program        = ALPHA *( ALPHA / DIGIT / "-" / "_" / "." )
version        = semver
guest-route    = *pchar *( "/" *pchar )
```

## 5. Create URI

No, I don't. `service` Query Parameters URI Organisation Create Intent:

```text
actr://notes.example/team-notes@1.4.2
```

Semantics:

- Download/Read Precision Program Release;
- Select a Realm namespace, defaulting to the local `local` namespace;
- Create a new Realm in that namespace (`local_name` generated by Actro, editable by the user); the instance is never placed in an existing Realm;
- Create a new Service in the new Realm;
- Select or Create Workspace;
- Replace address in situ after success with Attach URI.

A Create URI may specify a DNS namespace with the `namespace` parameter:

```text
actr://notes.example/team-notes@1.4.2?namespace=team.example
```

- The value is a normalized DNS domain with the same rules as a Publisher: lowercase IDNA A-label, no port, userinfo or IP literal;
- When omitted, the local `local:<installation-id>` namespace is used; the `local` namespace cannot be written in a URI;
- The namespace must already be trusted or be trusted for the first time on the confirmation page; when a Provider-owned namespace is used, the confirmation page must state that the trust root is that Provider;
- `local_name` is not part of the URI; it is decided on the confirmation page.

Create URI is an operational intent, not a permanent address of an existing resource. URI Equivalent to“New Template”.

### 6.1 `service`

- Value is Actr Normative `ActorId` String UTF-8 percent-encoding;
- Must fully include the Realm reference (namespace + `local_name`), serial and ActrType; no numeric `realm_id`;
- After parsing ActrType I have to. URI It's... publisher/program/version Exactly the same;
- One is not allowed. query Multiple `service`;
- (a) Empty values are not allowed;
- Not allowed Actor Type, aliases, market ID Or local database ID Alternative.

### 6.2 `realm`

A v1 ActorId must itself carry the Realm reference, so an Attach URI needs no second locating parameter. Actro derives the Realm from `service`:

```text
2af01@notes~dns:team.example/notes.example:team-notes:1.4.2
```

`realm` is used in one case only: when importing a current Actr legacy ActorId (which carries only a numeric `realm_id`), it explicitly supplies the full Realm reference, e.g. `?realm=notes~dns:team.example` (percent-encoded). Create URIs no longer use `realm`; they use `namespace`, and a Create URI containing `realm` is rejected.

After a legacy Attach resolves successfully it must be upgraded to a v1 ActorId carrying the Realm reference, and `realm` is removed from the normalized URI. `realm` and `service` must not remain two potentially contradictory sources of location.

A local Realm ActorId uses the `local:<installation-id>` namespace, e.g. `2af01@h3x8p2wq~local:<installation-id>/...`. It can be reconnected precisely on this machine but cannot be resolved by other devices; Actro must disable“Copy portable link”rather than forge a DNS namespace.

## 9. Parsing algorithm

```text
parse(uri):
  1. Authentication scheme
  2. Authentication authority Just... publisher host
  3. Normative publisher
  4. Parsing program@exact-version
  5. Parsing guest route
  6. Ripping and Heavy reserved query
  7. If service Missing:
       reject realm; normalize optional namespace (default: local namespace)
       → CreateIntent (the new Realm is created after confirmation)
  8. If service Exists:
       reject namespace
       parse ActorId, extract Realm reference (namespace, local_name)
       assert ActorId.type == coordinate
       DNS namespace:
         fetch https://<domain>/.well-known/actr (authority descriptor)
         verify the realm_namespace member's signature and rotation
           chain with the pinned namespace key; reject sequence rollback;
           if the signing key of an accepted Profile has been removed
           from keys, discard that Profile and its sequence baseline and
           fall back to the last accepted Profile signed by a still-listed
           key; if none, refetch as if none had been accepted
         fetch the Realm Profile via the realms relation, verify it
           with the namespace key
         assert profile.namespace/local_name == ActorId Realm reference
         assert profile.sequence does not roll back (else URI_REALM_PROFILE_INVALID)
         assert provider.id matches the accepted Profile (else REALM_PROVIDER_MISMATCH)
         assert profile.status != retired
         any failure → fail closed: reject Attach and
           MUST NOT fall back to the default provider in services
       local namespace (no Profile):
         assert installation-id == this installation and a local record exists
       → AttachIntent
  9. fragment As Guest Status Save
```

Steps 1–7 and the syntactic part of step 8 only produce intent objects; they do not download packages or create a Service. Fetching the authority descriptor and Profile in step 8 is the network part of Realm resolution and likewise must run only after user confirmation and policy checks; results may be cached.

The `realm_namespace` member and the `realms` relation are defined in Actr Authority Discovery §4.3–4.4. Protocol object fields are snake_case (e.g. `realm_namespace`, `local_name`).

If the Realm Profile cannot be fetched, fails verification or is retired, Actro must fail closed: it connects to no Actor of that Realm and must not use the default provider in the authority descriptor's `services` to talk to that Realm; the default provider is only a suggestion when creating a new Realm.

## 13. URI Error Code

| Code | Meaning |
|---|---|
| `URI_SCHEME_INVALID` | Not supported scheme |
| `URI_PUBLISHER_INVALID` | Publisher Not an official domain name |
| `URI_PORT_NOT_ALLOWED` | Official Publisher Port |
| `URI_PROGRAM_INVALID` | Program Syntax: |
| `URI_VERSION_REQUIRED` | Missing exact version |
| `URI_VERSION_INVALID` | Version is not allowed SemVer |
| `URI_RESERVED_DUPLICATE` | Repeat retention parameters |
| `URI_ACTOR_ID_INVALID` | Service ActorId Could not close temporary folder: %s |
| `URI_ACTOR_TYPE_MISMATCH` | ActorId type with Program coordinate Not in line |
| `URI_NAMESPACE_INVALID` | `namespace` is not a valid normalized domain (port, IP literal, etc.) |
| `URI_NAMESPACE_NOT_ALLOWED` | `namespace` in an Attach URI, or `realm` in a Create URI |
| `URI_REALM_REQUIRED` | Legacy ActorId lacks a Realm reference and cannot be imported |
| `URI_REALM_MISMATCH` | Legacy `realm`, Realm Profile and the ActorId's Realm reference disagree |
| `URI_REALM_NAMESPACE_INVALID` | The authority descriptor lacks `realm_namespace`, or its signature or rotation chain is invalid, or its `sequence` rolled back |
| `URI_REALM_PROFILE_UNAVAILABLE` | The Realm Profile cannot be fetched via the `realms` relation; fail closed, no fallback to the default provider |
| `URI_REALM_PROFILE_INVALID` | The Realm Profile signature is invalid (including a signing key that has been removed), its `sequence` rolls back, or it does not match the ActorId's Realm reference; fail closed |
| `REALM_PROVIDER_MISMATCH` | A new Profile's `provider.id` differs from the accepted Profile (a Realm is bound to its Provider for life; see the error codes in 12); fail closed |
| `URI_REALM_RETIRED` | The Profile of the ActorId's Realm is retired |
| `URI_LOCAL_REALM_FOREIGN` | Local Realm ActorId does not belong to this installation |

Error code for logs, tests and developers; user files must state the operational reasons.
