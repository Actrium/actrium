# 原则、威胁与语义模型

本章给出长期稳定的判断依据：原则、默认威胁，以及协议各章共用的概念。后续章节不得重新定义这些词，也不得用实现名称代替规范含义。

## 1. 九条原则

1. **结论绑定当前就绪切面。** 保障作用于这次核对里一致的结构、实例事实、证据和策略，不作用于应用名称或脱离状态的静态实例。相关事实一变，旧结论失效。绿色不表示曾经存在一个全图同时世界。
2. **数据权力必须来自显式授权。** 加入图、建立连接、同属一个 Principal，都不自动产生数据权力。授权者不能转出自己没有的权力。新配置只作用于新数据；旧数据适用取得时声明与当前声明的交集。
3. **外部性必须被完全中介。** 凡是可能让边界外主体观察、取得、保留或影响应用信息的行为，都必须经过不可绕过的执行点。
4. **可执行能力才是系统事实。** 安全计算使用的是实际可能效果的闭合上限，不是开发者愿望清单，也不是尚未发生的运行记录。
5. **信任绑定身份、状态和范围。** 主体信任与实例信任分开；信任不跨 Actor 传播，也不能跳过证据核验。
6. **保障绑定事实必须原子演进。** 能力、配置或环境变化时，声明与实际能力同步切换；变化 Actor 进入保障挂起，旧权力立刻失效。已持有数据的世代不得改写成新状态。
7. **组合不可补偿。** 一个未受控或未知出口，不能被更多绿色节点、品牌或综合分数抵消。同一评定上下文的多份结论取最弱项，不能挑选较绿的验证者。
8. **未知必须诚实保留。** 缺证、过期、错域或无法验证，结果是未知，不是「暂当安全」，也不是自动判恶意。
9. **数据生命周期必须本地闭合。** 最高保障不得依赖失联后再向远端发清理命令。交付前就要建立本地可独立收口的使用边界。

派生规则：默认拒绝；未声明即不可用，不能排除即纳入；失败关闭；证明必须能阻断数据面；同意可以接受风险，但不能改写事实；无法判断是否依赖变化节点则停。

## 2. 威胁与信任

### 2.1 默认攻击者

模型默认不依赖对方自愿守约。需要覆盖的主体至少包括：恶意或被攻陷的 Guest / Service、网络攻击者、不受信的信令与 TURN、能读普通内存的基础设施运营者、供应链替换与回滚、本地同用户进程，以及错误配置的内部人员。

「不受信任」表示不能把它的承诺当事实，不表示已经确认它作恶。没有被可信机制排除的能力，按可能被使用计算。

### 2.2 角色不自带信任

前台、本地、官方、后端、Edge、Realm 都只是角色或部署标签。它们不产生特殊安全规则，也不自动进入信任根。用户是当前信任策略的最终选择者；产品可以给默认建议，不能把默认写成协议里不可取消的固有信任。

### 2.3 主要 TCB

必须明确纳入或明确排除：

- Actro / Host 中负责能力执行、状态权威和结论执行的部分；
- Actor 身份与安全通道实现；
- 验证者、评定规则和密钥释放路径；
- 被某一 Profile 点名的 OS、硬件、TEE 固件和厂商证明根；
- 发布与更新信任根。

Guest、第三方 Native、外部 API、Realm 运营者和云平台默认不在 TCB 内。Realm 可以影响发现、元数据和可用性，但不得成为消息明文端点或应用保障权威。

### 2.4 基础假设

普通 Profile 可以假设：现代密码原语未被攻破；用户设备基础 OS 在常规威胁下可用；配置的根证书起初正确。普通本地 Profile 不声称抵御已完全控制内核的攻击者，也不消除用户对自己已看见明文的复制或拍照。

## 3. 概念

**Actor**  
唯一规范节点类型，也是宏观通信与执行边界。可以是一台 VM、一个进程或其他能以 Actr 身份运行的单元。规范不强迫按内部组件拆分。

**ActorId / ActorStateId**  
前者回答「这是哪个实例」，后者回答「它现在准确处于什么状态」。

**Actor 实例**  
`(节点应用 + 实例配置) + 宿主环境`。节点应用包括 Workload、Host 软件、Manifest 和装载闭包；宿主环境是包外的 OS、虚拟化、硬件、TEE、管理员边界等。

**Principal**  
当前使用该实例的一方。一个 Actor 实例完整生命周期只绑定一个 `PrincipalId`。`PrincipalId` 是外部给定的不透明标识；本模型只引用、比较和绑定，不定义其生成与现实身份治理。

**有效能力声明**  
Actor 当前实际可能造成的全部规范效果的闭合上限，也是安全计算的唯一能力清单。Manifest 只是输入。未列入的效果必须在结构上不可用；无法排除的效果必须补入。

**能力效果**  
V1 只有两种：

- `Transfer(target)`：应用信息可能被边界外的指定目标取得；
- `Retain`：预先确定的临时使用边界结束后，Actor 或其宿主环境仍能恢复应用信息。

**Capability**  
权力来源直接签发给目标 `ActorId + ActorStateId` 的自包含授权。它决定某个动作现在能不能做，不裁剪有效能力声明，也不是安全结论。

**数据输入授权**  
决定麦克风、摄像头、文件等数据是否进入应用。它与颜色正交。

**风险接受**  
用户在了解当前黄 / 红事实后允许继续运行。只影响运行许可。

**ActorState / ActorAssurance**  
前者是实例事实的不可变原子记录；后者是验证者针对准确 `ActorStateId`，在特定证据、策略、规则和有效期下给出的结论。

**应用图**  
由有效 `Transfer(ActorId)` 依赖形成的无根最大连通组。当前是否在线、是否通信，不改变成员。

**数据世代**  
每份已进入 Actor 的应用数据带有取得世代，等于取得时的 `ActorStateId`。对新产生或新接收的数据，适用当前有效声明；对旧数据，适用「取得时声明 ∩ 当前声明」。能力扩大不能让旧数据走新出口；能力缩小同样立刻关掉已删除的出口。

**读一致切面**  
`ApplicationAssurance` 承诺的是发布核对时刻对当前指针的一次一致读取，不是全部 Actor 内部状态的同一物理瞬间。

**验证者汇聚**  
同一评定上下文（`ActorStateId` + 策略版本 + 规则集）下，所有被接受的 `ActorAssurance` 取最弱项。不能挑选较绿的一份。不同策略是不同评定，不是打架。

**出口事实**

| 事实 | 含义 |
| --- | --- |
| `CONTROLLED` | 出口在有效声明中，范围被不可绕过控制，且命中当前可信行为模式 |
| `UNKNOWN` | 缺少足够依据排除暗出口或确认约束 |
| `UNCONTROLLED` | 已确认存在不符合可信边界的泄漏能力，或已确认存在 `Retain` |

`UNCONTROLLED` 表示能力存在，不等于已经观测到泄漏。

## 4. 能力语言

```text
EffectiveDeclaration
  = DeveloperManifest
  ∪ HostProvidedEffects
  ∪ EnvironmentUnexcludedEffects
  − EffectsStructurallyProvenImpossible
```

文字说明、用途、保留时长、API 名称和「只发送统计数据」等自述，不得缩小 V1 的技术事实。Host 不能强制限制载荷时，该 `Transfer` 按可能包含 Actor 可访问的任意应用信息计算。

指向具体 `ActorId` 的 `Transfer` 同时形成图依赖边，但不自动授予发送权。目标与发起方 Principal 不同、或依赖无效时，对方不入图，该出口仍按发起方的效果计分，且不得判受控。非 Actor 目标（屏幕、文件、Workspace、域名、API）表示为 Host 可判定、可强制的目标集合；精确地址不等于目标可信。直连与 TURN 同义：只接触端到端密文的中介不是明文目标，不入图。

`Retain` 是二元事实。能恢复就是存在，映射为未受控；无法确认按可能存在处理；只有证明边界后不可恢复，该项才消失。保留一分钟与永久不形成不同安全等级。

## 5. 应用图与四对象

图只做两件事：找到必须一起评的完整 Actor 集合，并给这套结构一个不可混淆的身份。没有根，没有另行维护的成员名单，没有边级或子图分数。

```text
ActorStateId
    ↓ 受信验证者评定并签名
ActorAssurance
    ↓ 与完整应用结构一起进入 Merkle 承诺
ApplicationStateId
    ↓ 受信应用评定者评定并签名
ApplicationAssurance
```

Merkle 叶子、成员证明、修订号和变化事件是实现材料，不是第五种顶层心智对象。

逻辑依赖结构改变，是另一份应用结构；配置、环境、证据变化，是同一结构的当前状态变化。两种情况都会使旧结论失效。仅连接或空闲变化不改结构。

## 6. 顶层计算

```text
ActorControlled(a)
  := 每个不能排除的 Transfer 都有当前、有效、受信
     且绑定准确状态的依据证明它受控，
     并且有充分依据确认不存在 Retain

ApplicationGreen
  := GraphValid
     AND ChannelsValid
     AND Ready
     AND 每个 Actor 都 ActorControlled

ApplicationRed
  := 存在已确认的 UNCONTROLLED 出口

ApplicationYellow
  := 非红，且存在至少一项必要 UNKNOWN
```

没有平均值、权重、调用频率或业务重要性。99 个受控节点抵消不了 1 个任意外发出口。上式是切面内的评定；对外展示绿 / 黄 / 红还须 `Ready`。挂起或快照过期时，不得把切面颜色当成当前展示。

核心链还须满足：精确绑定、抗拼接、抗重放、局部验证、增量重算、失败关闭、遍历无关、无唯一存储依赖，数据世代隔离，以及「结论失效不等于所有进程停机」。`Ready` 是当前指针一致且全部成员 `ACTIVE`；绿色相对于这次就绪切面，不相对于一份脱离当前指针的历史结论。
